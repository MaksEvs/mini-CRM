# Контур — мини-CRM «Объекты и задачи»

Мини-CRM для строительной компании: постановщик управляет объектами и задачами, исполнитель выполняет назначенные ему задачи. Стек: React, TypeScript, Vite, MUI, Supabase Auth и PostgreSQL с RLS/RPC.

## Запуск

Требуются Node.js 22+ и npm.

1. Установите зависимости: `npm install`.
2. Создайте `.env.local` в корне проекта и укажите настройки своего проекта Supabase:

   ```dotenv
   VITE_SUPABASE_URL=https://<project-ref>.supabase.co
   VITE_SUPABASE_PUBLISHABLE_KEY=<publishable-key>
   ```

   Допускается публичный anon key через `VITE_SUPABASE_ANON_KEY`. Не указывайте `service_role` или secret key в клиентских переменных.

3. Примените SQL-миграции из `supabase/migrations` по порядку через Supabase SQL Editor.
4. В Supabase Authentication создайте одного постановщика и двух исполнителей. Для каждого пользователя добавьте запись в `public.profiles`, используя UUID из Auth:

   ```sql
   insert into public.profiles (id, full_name, role) values
     ('<manager-auth-user-uuid>', 'Постановщик', 'manager'),
     ('<executor-1-auth-user-uuid>', 'Исполнитель 1', 'executor'),
     ('<executor-2-auth-user-uuid>', 'Исполнитель 2', 'executor');
   ```

5. Запустите приложение: `npm run dev`.

Публичной регистрации нет. Создание пользователей и управление ролями выполняются администратором в Supabase. `.env.local` не добавляйте в репозиторий.

## Функциональность по ролям

**Постановщик (`manager`)** видит все объекты и задачи, управляет объектами и задачами, назначает исполнителей, просматривает историю, принимает задачи на проверке или возвращает их с обязательным комментарием.

**Исполнитель (`executor`)** видит только назначенные ему задачи и связанные с ними объекты. Может переводить свою задачу `Новая → В работе → На проверке`, а после возврата — `На доработке → В работе`. Создание, редактирование, удаление и принятие задач исполнителю недоступны.

Статусные переходы и доступ к строкам проверяются базой данных, а не только интерфейсом. История формируется базой при создании задачи и смене статуса. Открытие регистрации и смена роли из приложения не предусмотрены.

## Кратко для руководителя

Система хранит строительные объекты, назначенные по ним задачи и историю изменений. Постановщик создаёт объекты и задачи, назначает ответственных и проверяет результат. Исполнитель видит назначенные ему задачи, отмечает начало работы и отправляет результат на проверку. Постановщик принимает задачу или возвращает её с комментарием.

Доступ выдаётся после входа по учётной записи, которую заранее создаёт администратор. У каждого пользователя своя роль. Ограничения действуют не только на кнопки в приложении: база данных тоже проверяет, кто вошёл, какие записи ему доступны и разрешено ли действие. Поэтому исполнитель не может получить чужую задачу или выполнить запрещённое действие простым обходом интерфейса. История статусов сохраняется автоматически. Для подключения используются публичные ключи Supabase; секретный ключ администратора в браузер помещать нельзя.

## Решения, допущения и ограничения

- В системе две роли: постановщик и исполнитель; у пользователя одна роль, у задачи один исполнитель. Роли и учётные записи назначаются администратором, открытой регистрации нет.
- Исполнитель работает только со своими задачами и связанными с ними объектами. Он не может создавать, изменять или удалять объекты и задачи, переназначать исполнителя, принимать задачу или возвращать её на доработку.
- Удаление объекта с задачами блокируется связью в базе данных. При удалении задачи её история удаляется вместе с ней; отдельные операции изменения истории пользователям запрещены.
- Возврат на доработку требует комментария. После принятия задача остаётся в конечном статусе; повторное открытие не предусмотрено.
- Применение миграции, создание пользователей и ручное создание их профилей выполняются владельцем проекта в Supabase Dashboard. В локальной среде можно проверить сборку и статический анализ, но это само по себе не подтверждает подключение к облачной базе или работу настроенного проекта.
- **Не подтверждено/не выполнено в рамках локальной проверки:** развёртывание на Vercel и ручная проверка сценариев в браузере с реальными аккаунтами Supabase. Для этого владельцу проекта нужно настроить Supabase, применить миграцию, создать профили, задать переменные окружения и отдельно выполнить деплой.
- Автоматические тесты бизнес-сценариев в репозитории не настроены; перед эксплуатацией рекомендуется вручную проверить роли и запрещённые действия на тестовых аккаунтах.

## Проверки проекта

Локально запускались `npm run format`, `npm run format:check`, `npm run build` и `npm run lint`. Они прошли успешно. Сборка выводит предупреждение Vite о JavaScript-файле больше 500 кБ. Проверки не заменяют применение миграции и тестирование с настроенным Supabase.
